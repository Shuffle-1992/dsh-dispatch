# ZB-42 交付：冻结开关不再挡住只读探测（+ BOM 静默失效加固）

## 用户现场报告

> 「现在 Zcode 那边没有任何通道可以调用」——重启后面板**看不到任何通道**，还报「通道清单加载失败」，
> 看起来像插件坏了（用户因此关掉开关避免 Agent 撞失败）。

## 真因（不是改名引起的）

**ZB-33（2026-10-11 提交 `2f8aa20`）把总开关闸门提到了 runner 的最前面**当"第一道闸"。
动机是对的（冻结时连 `config.json`/凭据库都不去碰），但**连带把只读的 `--list-providers` 也挡住了**：

```
闸门(150)  →  参数解析  →  --list-providers 分支(345)   ← 原先：探测被闸门挡住，永远到不了这里
```

⇒ 总开关一关，`--list-providers` exit 3 不输出任何内容 ⇒ core 拿到空 stdout ⇒
`channels: []` + 警告「list-providers 输出为空」⇒ 面板显示「通道清单加载失败」。

**时间线核对**：ZB-33 落在 10-11；我上次探测通道是 10-07（闸门当时还在后面），所以此前没暴露。
**与本轮改名无关**（改名只动了路径字符串）。

## 修法（两侧 + 一处加固）

### ① runner：闸门下移到只读分支之后

```
参数解析  →  --list-providers 分支（纯读，放行）  →  ★GATE★  →  凭据读取  →  子进程启动
```

- **只读探测放行**：不派发、不启动进程、不消耗额度 ⇒ 冻结期间面板照常列通道。
- **一切真实派发仍必过闸**（exit 3）；闸门**仍早于凭据读取与 spawn** ⇒ ZB-33 的收益完整保留。

### ② 面板：冻结时明说「冻结 ≠ 故障」

`ChannelSection` 增加 `sw` prop；`sw.enabled === false` 时在「通道」分区顶部渲染
`switchOffBlocked`（**复用既有 locale 键**——该键此前只出现在 agent 工具描述里，面板从未渲染过，故不新增文案键、单源哨兵不受影响）。

### ③ 加固：BOM 静默失效（修 B 时实测撞到的真实隐患）

排查过程中发现：**带 UTF-8 BOM 的开关文件会让冻结静默失效**。

- 成因：PowerShell 5 的 `Set-Content -Encoding UTF8`、Windows 记事本"另存为 UTF-8"都会写 BOM（`EF BB BF`）；
  `JSON.parse` 遇 BOM **必抛** ⇒ 命中 `readDispatchSwitch` 的 catch ⇒ **fail-open（返回 enabled:true）**。
- 实测复现：带 BOM 的 `{"enabled":false}` → 加固前**派发照常放行**；加固后 exit 3。
- 修法：解析前 `.replace(/^\uFEFF/, '')`。BOM 与"文件损坏"无关，剥掉即可。
- ⚠️ 对安全闸门，**静默失效比报错更危险**，故单列一条并加测试锁。
