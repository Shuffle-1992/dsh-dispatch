## 二、两个「不是要求、但会直接卡住安装」的硬伤（本轮实测发现）

### 硬伤 A：仓库根没有 `package.json` ⇒ 从仓库安装**装不到插件**

插件在子目录 `zcode-dispatch/`，仓库根只有 `README.md`/`.gitignore` 等。pnpm 实测（`pnpm add github:Shuffle-1992/dsh-dispatch`）：

```
[WARN] The git-hosted package fetched from ... has to be built but the build scripts were ignored.
+ zcode-dispatch 0.0.0
```

装出来的 `node_modules/zcode-dispatch/package.json` 内容是：

```json
{"_pnpmPlaceholder":"This file was generated by pnpm. The original package did not contain a package.json."}
```

而真实文件（`bridge/`、`collab-kit/`、`tasks/`、`zcode-dispatch/`…）全被平铺进了包根 —— **插件本体在 `zcode-dispatch/` 子层**，`index.js` 根本不在包根，DSH 加载会失败。

**修法（用户已选定）**：保持子目录结构，README 用 pnpm 的 `#path:` 语法指向子目录。实测可行：

```
pnpm add github:Shuffle-1992/dsh-dispatch#path:zcode-dispatch
  → + @local/zcode-dispatch 0.1.0        （解析到真包，非占位）
```

### 硬伤 B：`@local/*` 不是可发布的 npm 身份

- DSH 侧语法校验（`dsh-plugin-manager/lib/types/install-spec.js` 的 `PACKAGE_NAME`）**通过** `@local/zcode-dispatch`；
- 但 `@local` 是**本地 link 约定**，不是可发布的 npm 作用域 ⇒ 市场「复制安装命令」这条链走不通。
- 社区先例：已装 4 个社区插件**全是裸名** —— `dsh-pet`、`dsh-cost-meter`、`dsh-connect-trae`、`dsh-workbuddy-connect`，`license` 全 `MIT`，`keywords` 全含 `dsh-plugin` + `deepseek-harness`，`repository` 全指向各自 GitHub。
- npm 占用实测：`dsh-zcode-dispatch` 与 `zcode-dispatch` **均未被占用**（registry 404）。

**修法（用户已选定）**：改为裸名 **`dsh-zcode-dispatch`**。

> ⚠️ 改名**不是纯元数据操作**：官方 typert-loader 有一条硬校验
> （`refs/dsh-typert/loader/lib/index.js:80`）：
> ```js
> if (manifest.package !== pkgName) throw new Error(`typert-loader: ${pkgName} TYPERT manifest names package ${...} — the manifest must be owned by the package that exports it`);
> ```
> 即 `TYPERT.package` 必须**逐字等于** npm 包名。改名必须同步 `wire.host.mjs` 的 `TYPERT.package`、
> 所有 `typeSymbol` 前缀、`client.js` 的 `__ModuleLoader__.load({id})`、`cordis.patch.yml` 的
> `name:`、以及 `tools/verify-plugin.mjs` / `test/z2-verify.mjs` 的断言 —— 漏一处则**加载即失败**。

## 四、DSH 侧的权威依据（用于判「什么才是必需的」）

| 事实 | 证据位置 |
|---|---|
| `name` 与 `version` 必填；`dsh.manifestVersion` / `engines.dsh` 可选 | `@deepseek-ai/dsh-package-manifest` README（解包） |
| `dsh.bundle.patch` = 一个路径或有序路径列表，相对包根 | 同上；消费点 `@deepseek-ai/dsh-app-boot/lib/index.js` |
| 安装命令形态 `dsh plugin --profile <name> add <spec>` | DSH 文档（解包）：`dsh plugin --profile web add @deepseek-ai/dsh-experimental-agent-team-profile` |
| 实际执行 `pnpm add <spec>`（spec 原样透传） | `dsh-plugin-manager/lib/index.js`：`this.runPnpm(["add", spec, ...])` |
| 安装 spec 支持 git shorthand / URL / tarball / 绝对路径 / registry 名 | `dsh-plugin-manager/lib/types/install-spec.js` |
| typert manifest 的 `package` 必须等于包名 | `refs/dsh-typert/loader/lib/index.js:80` |
| 官方插件开发技能把 `install_bundle`/`plugin_manager` 作为安装路径 | `@deepseek-ai/dsh-agent-preset/skills/cordis-plugin-development/SKILL.md` |

> **关于 `dsh-skill` / `agent-skills` topic**：那两项是**Skill 包**的要求。本包是 Cordis 插件
> （有 `index.js` 的 `apply(ctx, config)` + `dsh.bundle.patch`），**不适用**，无需添加。
